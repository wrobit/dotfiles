# Deep Research

Research for teaching, not for link-dumping.

## Use this for

- Turning a broad topic into a teachable sequence.
- Grounding explanations in both repo context and external sources.
- Surfacing misconceptions before the teaching phase starts.

## Goal

Use the codebase and the web to turn a topic into teaching-ready material.

## Loop

1. **Scope**
   - Restate what the user wants to learn.
   - Narrow the topic if it is too broad to teach well in one pass.
2. **Assess prior knowledge**
   - Search the codebase for existing usage of the concept or adjacent patterns.
   - Use that to infer what the user likely already knows.
3. **Gather from the codebase**
   - Find implementations, utilities, config, and tests that show the concept in real use.
4. **Gather from the web**
   - Prefer official docs, specs, and high-signal explanations over random summaries.
   - Look for common pitfalls, competing perspectives, and historical context.
5. **Synthesize**
   - Extract core concepts, prerequisites, project context, misconceptions, trade-offs, and open areas.
6. **Hand off**
   - Recommend a teaching order instead of dumping raw notes.

## Guardrails

- Prefer authoritative sources over blog spam.
- Synthesize conflicting advice instead of pretending there is one obvious answer.
- If you cannot see a teaching angle yet, stop gathering and narrow the topic.

## Timebox

If you have looked at 15+ sources without a clear teaching angle, stop, summarize, and ask the user to narrow the focus.

## Deliverable

- Research summary
- Core concepts with confidence level
- Prerequisites
- Existing project context
- Common pitfalls
- Perspectives and trade-offs
- Recommended teaching order
- Open areas that need deeper follow-up
